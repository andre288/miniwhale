## The Problem

When a container breaks in production (or in your local environment), you open the terminal, run `docker logs <container>`, and get bombarded by hundreds of lines. Which error actually matters? Why did it happen? What should you do?

Tools like Datadog and Dynatrace solve this — but cost hundreds of dollars a month and require an entire observability stack to run.

**MiniWhale** is the self-hosted, open source, Docker-focused alternative that any developer can run locally in under 5 minutes.

---

## How It Works

```
Docker Containers
      │
      ▼
  FastAPI (backend)
  ├── Collects logs via Docker SDK
  ├── Filters and groups similar errors
  └── Sends to AI model
            │
            ▼
        AI Analysis
        ├── Error description
        ├── Probable cause
        └── Suggested fix
            │
            ▼
    Next.js (webapp)
    └── Real-time dashboard via SSE
```

---

## Features

- **Real-time monitoring** — logs captured continuously via Docker SDK
- **Intelligent grouping** — similar errors grouped, not duplicated
- **AI analysis** — description, probable cause, and suggested fix generated by AI
- **Visual dashboard** — clean web interface with filters by container and severity
- **Zero external dependencies** — runs entirely locally, just needs an API key
- **Self-hosted** — your logs never leave your machine (except to the AI API)

## Installation

### 1. Clone the repository

```bash
git clone https://github.com/your-username/docker-log-monitor.git
cd docker-log-monitor
```

### 2. Set up environment variables

```bash
cp .env.example .env
```

Edit `.env` and add your API key:

```env
ANTHROPIC_API_KEY=sk-ant-...
```

### 3. Start with Docker Compose

```bash
docker-compose up --build
```

Open `http://localhost:3000` and you're good to go.

## Interface

### Main Dashboard
Lists all active containers with a visual health indicator. Errors are displayed grouped by similarity, with a severity badge, occurrence count, and last-seen timestamp.

### Details Panel
Clicking on an error group opens the full panel with:

- Stack trace with syntax highlighting
- **Description** — what this error means in plain language
- **Probable cause** — what likely triggered the problem
- **Suggested fix** — how to resolve it, with code examples when applicable
- Occurrence history and affected containers

## Advanced Configuration

All options live in `.env`:

```env
# Anthropic
ANTHROPIC_API_KEY=sk-ant-...

# Docker
DOCKER_SOCKET=/var/run/docker.sock

# Monitoring
LOG_WINDOW_SECONDS=60          # error grouping time window
LOG_TAIL_LINES=200             # log lines read per cycle
MIN_SEVERITY=error             # minimum: info | warning | error | critical

# Containers (optional — default: all)
INCLUDE_CONTAINERS=api,worker  # monitor only these
EXCLUDE_CONTAINERS=nginx       # ignore these
```

## API

Interactive API documentation is available at `http://localhost:8000/docs` (Swagger UI).

Main endpoints:

| Method | Route | Description |
|--------|-------|-------------|
| `GET` | `/containers` | List active containers |
| `GET` | `/containers/{id}/logs` | Paginated logs for a container |
| `GET` | `/errors` | Error groups with AI analysis |
| `GET` | `/errors/{id}` | Details for a single error group |
| `POST` | `/errors/{id}/analyze` | Re-analyze an error group with AI |
| `GET` | `/stream/errors` | SSE stream of new errors |

## Known Limitations

- Designed for local and development Docker environments; not a replacement for large-scale production observability
- Very high log volumes (>10k lines/min per container) may require tuning `LOG_TAIL_LINES`
- AI analysis has a per-call cost on the Anthropic API; error hash caching keeps usage low
